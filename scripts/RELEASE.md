# Gate de release isolado

O build normal exige `.qa/release-attestation.json` correspondente ao conteúdo de fontes, testes, migrations, configurações, dependências e assets. Sem evidência ou após qualquer mudança material, o build bloqueia antes de declarar sucesso. Documentação e o próprio atestado ficam fora do fingerprint; arquivos texto usam LF normalizado para Windows/Linux.

Antes de merge/release, execute `pnpm test:release` com `DG_TEST_DATABASE_URL` apontando para PostgreSQL **local, isolado, UTF8**, cujo nome contenha `test`, `review`, `qa` ou `e2e`. Configure `DG_PREVIEW_FILES_DIR` como diretório absoluto separado para arquivos privados de testes e `TEST_ARTIFACT_DIR` como diretório externo ao código para logs/imagens. Instale as dependências pelo lockfile e tenha o Chromium do Playwright disponível. A porta 3000 deve estar livre. Nunca use credenciais ou dados reais.

O runner aplica migrations sem seed de contas, recusa integrações IA configuradas, executa segurança/domínio/CSP, testes PostgreSQL de clientes e rollback de auditoria, compila e inicia uma aplicação local temporária. Executa os fluxos completos API/browser do compositor, acabamentos, textos técnicos, Databook, publicação, isolamento, contrato público, clientes e matrizes 390/768/1600. Para após vinte minutos e encerra seus processos. A inicialização local anterior ao atestado exige contexto de testes isolado e é rejeitada em Vercel.

O atestado só recebe `passed` quando todas as etapas e matrizes passaram e o fingerprint permanece igual ao início. Uma execução que falhou grava `failed`, invalidando o atestado anterior. Inclua `.qa/release-attestation.json` no commit e execute `pnpm test:release-verify` sobre o snapshot final. O campo `observedHead` registra a partida; a associação com o conteúdo final é o fingerprint, evitando dependência circular do SHA do commit que contém seu atestado. **O JSON é autodeclarado e não tem assinatura nem prova independente de proveniência**: o digest detecta mudanças materiais posteriores, mas não impede alguém com permissão para editar a PR de inventar uma execução. Trate-o como evidência revisável; um gate adversarial exige executor protegido e resultado confiável. Logs, cookies de fixtures e PDFs permanecem no diretório de artifacts; não os publique.

Este gate não usa GitHub Actions/Strix. Sua prova é local e reproduzível; exige registro da evidência no repositório para o build comum. Não certifica transporte remoto Vercel Blob, respostas de OpenAI real, dispositivos físicos/Safari/Firefox ou acesso ao preview protegido. Esses limites permanecem explícitos, e `Ready` sozinho não equivale à revisão final completa.

`scripts/security-route-audit.cjs` descobre cada rota API TS/TSX/JS/JSX e cada HTTP handler automaticamente. Apenas métodos públicos conhecidos são exceções. Resolve chamadas de guards obrigatórios, imports locais, aliases, delegações e reexports; imports não utilizados e novos métodos sem guard bloqueiam. É uma análise heurística, complementada pelas negativas reais API/browser: ela não prova a ordem nem todas as ramificações de autorização.
